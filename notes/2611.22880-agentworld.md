## 一句話
VLA world model 不該在像素層級想像未來；把場景壓成最多 20 個離散 `<agent_i>` token（每個綁一個周遭交通參與者的類別、3D box、未來軌跡與互動 context），讓 MLLM 在這些 token 上推理與規劃，比生成未來影格的同類方法更準也更快（作者自報）。

## 問題設定
- 對象是「VLA + world model」的自駕路線（FSDrive、VLA-World 這類會生成未來影格再規劃的模型）。
- 作者的診斷（Fig. 2，作者自報）：現有 VLA world model 用的 token 遠多於微調過的 Qwen2-VL 基底，規劃只小幅改善；而且**把影像線索拿掉，這些模型只掉一點點**，表示密集視覺 token 主要被拿去生成影像，沒有轉成規劃用的資訊。具體數字在 Fig. 2，待查 PDF。
- 問題被重新表述成：policy 應該在**哪一種 world state** 上推理。像素（太多無關細節）、BEV／occupancy（低階、背景與參與者糾纏）、global scene latent（把多個 agent 壓在一起、無法歸因）、語言描述（缺乏物理 grounding）都被列為不合適。

## 方法
1. **agent token 當 world state**：在 MLLM 序列裡插入固定 N=20 個特殊 token，token 的 embedding 本身就是 learnable query（不另設 object query）。MLLM 處理後，該位置的 hidden state 就是那個 agent 的 latent state；沒對到物體的 slot 學成 no-object。
2. **multimodal routed anchoring（只在訓練時用）**：每個 query 分兩路 cross-attend，一路接離線抽好的 **VGGT 類 4D 幾何特徵**（VGGT encoder 凍結不訓），一路接 MLLM 的 2D 視覺特徵；各自有 token-wise gate，兩模態不互搶。routing layer 數待查 PDF。
3. **physical grounding objective**：輕量 agent head 從 hidden state 預測類別／存在、3D box、未來軌跡，用 DETR 式 Hungarian matching 監督。監督對象不是所有標註物體，而是用 influence score（距離、是否在 ego lane、closing speed、未來最小距離、TTC、是否進入 ego corridor，對行人和自行車加權）挑出的 top-K 個（附錄 Alg. 1）。
4. **三段訓練**：
   - Stage 1 physical grounding SFT（12 epoch；MLLM、token embedding、routing、agent head 都訓）。
   - Stage 2 reasoning-oriented SFT（12 epoch）：輸出格式固定為 `<perception>`（只放 agent token）→ `<think>`（點名相關 agent 的簡短 rationale，例如「`<agent_3>` 正在穿越 ego 路徑，所以減速並維持車道」，rationale 可選用強 MLLM 生成）→ `<action>`（離散 meta-action：ACCELERATE／KEEP_SPEED／DECELERATE／STOP × KEEP_LANE／CHANGE_LEFT／CHANGE_RIGHT）→ `<answer>`（ego waypoints）。訓練中逐步丟掉 grounding scaffold，最後一段的輸入輸出格式和 RL 相同。
   - Stage 3 agent-oriented RL：GRPO 1 epoch，每個 prompt 取 8 個樣本，只更新 MLLM。reward = format + perception slot（agent token 數量、是否合法）+ meta-action F1 + trajectory（平滑度與模仿 expert，依 VLA-World）+ **agent interaction**（用**凍結的 agent head 從 agent token 解碼周遭 agent 的軌跡**，和取樣出的 ego 軌跡算最小距離與 TTC，懲罰碰撞、間距不足、TTC 過短）。權重預設全為 1。
5. **推論**：routing 模組和 agent head 都拿掉，只剩 MLLM 加學到的 agent token 介面。
6. **A.6 理論動機**：把未來影像拆成 agent 演化與 nuisance（紋理、光照、背景），假設規劃成本只依賴 agent state，則 agent state 是規劃的充分統計量；再假設成本對 agent state 是 Lipschitz，規劃 regret 受 agent state 預測誤差上界控制。式子在 HTML 看不到，待查 PDF。注意 checklist 對 theory 一題答 N/A，所以這段是動機，不是正式證明。

## 我對這篇的保留
1. **它不是 rollout 型的世界模型**。agent token 的「未來」只來自 agent head 對未來軌跡的監督（一次前向、一步預測），沒有把 world state 往前推多步，也沒有在想像中閉環。稱為 world model 是因為 hidden state 被訓成帶有未來運動資訊。這和我們說的「世界模型當模擬器」不同，引用時要講清楚。
2. **開環數字幾乎打平前作**。有 ego status 時，ST-P3 協定 Avg L2 0.25 vs VLA-World 0.26、UniAD 協定 0.40 vs 0.42，碰撞率差 0.01 個百分點。無 ego status 的同條件比較只有延遲表那一組（0.27 vs VLA-World 0.30），主表沒有。沒有 seed、沒有 error bar，這些差距在雜訊範圍內是否成立無法判斷。VLA-World 是同一組作者的前作（arXiv 2604.09059）。
3. **最有說服力的是 Table 8**（同條件下 agent tokens 0.27 vs global latent 0.49 vs structured text 0.58），但「structured text」和「global latent」的具體實作沒有寫清楚，也只有單一 run。
4. **RL 的 reward 有自我參照的風險**。interaction reward 用凍結的 agent head 解碼 agent token 的 hidden state，而 hidden state 是 MLLM 算的，RL 又在更新 MLLM。policy 理論上可以改變它「看到的其他車」來拿 reward（例如把周遭 agent 的預測軌跡推離 ego），只有 KL 到 SFT reference 在約束。作者沒有檢查 RL 前後 agent head 解碼品質是否改變。這正是「RL 鑽世界模型的錯」的一個具體形式。
5. **RL 是在記錄好的場景上做**（nuScenes 的開環樣本，reward 由規則和凍結 head 算），不是在世界模型裡 rollout。
6. Bench2Drive 閉環實驗的訓練資料（是否在 Bench2Drive 的 CARLA 資料上另外訓練）在我讀到的內文裡沒寫，待查 PDF 或 code。
7. grounding 依賴 3D box 標註和離線 VGGT 特徵，作者在結論承認這是限制（不是從規劃監督中自己長出來的）。
8. 延遲 0.31 s 約等於 3 Hz，離即時控制很遠。「比 VLA-World 快」是在 VLA world model 之間比，不代表語言骨幹的延遲問題解決了。

## 和我方向的關係

### 語言在這個架構裡承擔什麼
- 語言實際做的事：(a) Qwen2-VL 的預訓練表徵與 MLLM 骨幹；(b) prompt 裡的導航目標與指令；(c) `<think>` 的 agent-grounded rationale；(d) `<action>` 的離散 meta-action 標籤。agent 的物理狀態**刻意不用文字表達**，只存在 token hidden state 裡（附錄 A.1 的第一、二條原則）。
- **沒有任何「拿掉語言」的消融**：沒有「不輸出 `<think>`」的版本，沒有「換成非語言骨幹」的版本。Qwen2-VL-2B 原始 1.37 m 是「沒有任務微調」的對照，不是「沒有語言」的對照。所以這篇**不能**用來論證「語言是必要的」。
- 它反而提供兩個對我有利的證據：
  - Table 8：把 world state 寫成 structured text，L2 是三者中最差（0.58 vs agent tokens 0.27）。也就是說，在同一個 VLA 裡，**連 VLA 的作者自己都發現狀態不該用語言表達**。
  - meta-action reward 是三個 reward 裡拿掉後退化最小的（依內文描述）。
- 結論：在 AgentWorld 裡，語言主要是「骨幹的來源」和「輸出格式」，真正承載規劃資訊的是結構化的非語言 token。拿掉語言的代價**論文沒量**，這是一個空白，不是證據。

### 可以直接借用
- **合體版／B 版的動機段引用**（NeurIPS 2026，可正式引用，數字標作者自報）：
  1. 「像素層級的未來生成，多數 token 和規劃無關；把影像線索拿掉，現有 VLA world model 只小幅退化」（Fig. 2）。這支持「世界模型不該以像素為主要狀態」，也和 11-13 的 persistence 對照、11-19 CURE（畫質無法分辨好決策）同一方向。
  2. 「同骨幹、同監督下，結構化 token 比 global latent 和 structured text 都好」（Table 8）。可以寫成：即使在 VLA 內部，承載規劃的也是結構化的非語言狀態。
  3. 延遲：結構化狀態 0.31 s vs 像素想像 0.36–0.40 s。
- **token 介入測試的設計（Table 9）**：consistent permutation（打亂 slot 順序但保留 token 與 agent 的對應）vs mismatched permutation（破壞對應）。這是一個便宜、不需重訓的對照，可以直接搬到 P2：把 `z_pose` 的關節順序做「一致打亂」與「錯配打亂」，檢查 decoder 是否真的依賴關節身分，而不是 slot 索引。和 LASR（[2611.17775-lasr.md](2611.17775-lasr.md)）、ESC 的 swap probe 是同一類對照。
- **訓練時才用的 grounding head，推論時丟掉**：和主線 memo §3「只在訓練時用的動作結構先驗」完全同型。AgentWorld 的 head 回歸 3D box 與軌跡；我們的先驗回歸關節角度變化量。可以引用它當「訓練時結構監督、推論時零成本」的前例。
- **把凍結的結構化 decoder 當 reward 來源**：RL 時用凍結的 agent head 從 token 解碼結構化狀態再算 reward。對應到我們：凍結的計數器（或 pose decoder）從 latent 讀出「第幾下」，當 reward 或終止判斷。
- **influence score 挑 top-K**：只監督和決策有關的實體。週期任務的類比是只監督「正在做重複動作的肢段」。

### P2：latent action 在 2D 像素空間還是 3D／關節空間學
- AgentWorld 的論點是「規劃需要的狀態 = 結構化實體 + 3D 幾何 + 運動」，像素是間接而低效的介面。換到我的問題：P2 的 `z_pose` 就是把 latent action 的一部分錨定在關節空間（結構化、可解讀），`z_res` 留給 pose 描述不到的部分。
- 它支持的部分：(a) 結構化錨定 + 推論時丟掉監督頭可行；(b) 4D 幾何拿掉退化最多（0.27 → 0.30），2D 視覺拿掉退化較少（0.27 → 0.28），在自駕上「3D 比 2D 重要」。
- 它不支持的部分：它的結構來自**有 3D box 標註**的監督。P2 的 `z_pose` 監督來自 MediaPipe 從影片估出的 pose，有雜訊、會失效（bench_pressing 30% 偵測率）。AgentWorld 沒有信心門控，也沒有「結構失效時降級」的設計；P2 的 `z_res` 和信心門控是它沒有的部分。
- 它也沒有做「agent token vs 只用 2D 像素 latent」在**多步 rollout** 上的比較，所以「結構化狀態讓 rollout 更穩」仍是我們要自己證明的事（見 H1）。

### agent-oriented RL 放在哪一層
- 層級：RL 在 **policy 層**（更新 MLLM），world state 的 grounding 模組凍結，reward 的一部分由**凍結的 world-state decoder** 提供。資料是記錄好的場景，不是世界模型 rollout。
- 對照合體版：合體版是「世界模型當模擬器 → policy 在裡面做 RL」。AgentWorld 是「world state 當 policy 的中介表示 → RL 在真實紀錄上做，world state decoder 當 reward model」。兩者不同層，引用時不要把它寫成「世界模型內 RL」的例子。
- 但它示範了一件合體版也會碰到的事：**當 reward 由 policy 自己的內部表示解碼而來，RL 可能改變表示來拿 reward**（保留 4）。合體版用計數器當 reward 時，如果計數器讀的是世界模型 rollout 出來的影像或 latent，同樣的漏洞存在（RL 讓世界模型「生出」看起來數到 5 的畫面）。

### 威脅或差異點
- 不威脅「無語言 VA」的空位：它是 VLA，用語言骨幹、語言 rationale、語言 prompt。
- 不威脅週期／計數方向：沒有週期、次數、exemplar、長程 rollout。
- 差異點可以寫成一句話：AgentWorld 用**物體級**結構（agent token）取代像素；我們用**關節級**結構（pose 錨）加上**時間級**結構（重複動作對應重複碼）。它解決的是「哪些實體重要」，我們關心的是「動作的時序結構有沒有在 rollout 中保持」。

### 待驗證的想法（假說）
- **H1：結構化狀態在多步 rollout 上比像素 latent 更不會漂移。** AgentWorld 只做一步預測。在週期任務上，可以把 rollout 分別在像素 latent（例如 V-JEPA 2 特徵）與 pose 空間（P1 量尺）上量週期漂移，看「結構化」是否在長度上有優勢，還是只在一步預測上有優勢。依 11-19 RWM 稽核的教訓（one-step 好不代表 rollout 好），這個假說可能不成立。
- **H2：RL 的自我參照 reward 會讓結構化狀態的解碼品質在 RL 後下降。** 可以在任何「凍結 decoder 讀 policy 內部表示當 reward」的設定裡檢查：RL 前後用同一組 GT 評 decoder 的解碼誤差。如果 AgentWorld 公開 code 與 checkpoint，這是一個零訓練的檢查（先照 research_rules §1 重現它的 nuScenes 主數字）。
- **H3：一致／錯配 permutation 可以當 P2 的「關節身分」探針。** 預期：如果 `z_pose` 真的錨在關節空間，錯配打亂會讓 rollout 的週期指標明顯變差；一致打亂則不變（需要架構對關節順序 equivariant，否則一致打亂本身也會壞，要先確認）。
