# Body Schema Policy: Body as the Vision–Action Interface for Efficient Robot Loco-Manipulation（BSP）

- arXiv：https://arxiv.org/abs/2611.22713　｜　出現在日報：[2026-11-19](../digests/2026/2026-11-19.md)　｜　筆記日期：2026-11-20
- 作者／機構：Lechen Zhang, Chenyuan Chen, Muxin Zhou, Zewen He, Yoshihiko Nakamura；Mohamed bin Zayed University of Artificial Intelligence（MBZUAI）。**未經同儕審查**。
- Code／專案頁：https://www.lechen-zhang.com/BSP/ ；全文沒有 code 連結。
- 讀了哪些部分：全文（HTML 版）：摘要、§1–§6、LLM 使用聲明、參考文獻。**supplementary 不在 HTML 裡**（screw 指數的閉式解、FK 等價證明、訓練配方、統計慣例、各任務分項、latent 空間控制器的實驗都在 supplementary），以下標「待查 supplementary」。HTML 的數學式是空白；文中「fewer parameters」「at least × our error」等倍數在 HTML 裡缺字，下面的倍數是我用表格數字自己算的。

## 一句話
把 policy 的內部表示建在機器人的運動學樹上：每個關節、每個 link 各一個 token，用學出來的 screw motion 沿父子關係傳遞特徵；每個關節用自己的 token 去 query DINOv2 patch，取回自己需要的視覺證據，再條件化自己那一維動作的去噪。35M 參數、每個 action chunk 13.9 ms，在 9 個模擬 G1 全身任務上和 2.63B 的 Ψ₀ 打平（作者自報）。

## 問題設定
- 全身 loco-manipulation：機器人同時要走（或移動底盤）和精細操作，輸入是相機影像與本體感測（proprioception）。
- 現狀：最強的 policy（Ψ₀、π0.5、GR00T N1.6、DreamZero）有數十億參數，而且每個任務仍要用示範微調。
- 作者的診斷：一般 visuomotor 架構把動作當成扁平向量、影像當成所有動作共用的特徵（例如 Diffusion Policy 用一個 pooled 視覺表示條件化整個 chunk）。「關節怎麼一起動」「影像的哪部分對哪個身體部位重要」都要從示範裡重新學。
- 問題：把身體結構放進 vision-action 介面，能不能換到效率（參數、延遲、資料）。

## 方法
1. **policy 是 denoiser**：輸入 egocentric 影像的 patch tokens、本體狀態、目前的 noisy action chunk（作者稱 action hypothesis）與去噪步數，預測雜訊；DDPM 目標，訓練方式同 Diffusion Policy。
2. **latent body schema（§3.2）**：
   - 動作空間分兩部分：運動學樹上的關節目標（on-tree），和不屬於任何關節的控制指令（off-tree，例如底盤速度）。
   - token：每個關節一個 joint token、每個 link 一個 link token、加一個 global token。joint／link token 條件化 on-tree 動作；global token 條件化 off-tree 指令。
   - 三個 affine map 從「本體狀態 + 整個 action hypothesis + 去噪步」初始化所有 token：**每個 token 都看得到整個 action hypothesis**，而且每個去噪步都重建 schema。
3. **Neural Screw Operator（§3.2）**：
   - FK 的結構：link 的位姿 = 根部位姿 × 沿路徑每個關節 twist 的矩陣指數（screw motion，統一表示 revolute、prismatic、helical）。
   - 運算子：從 joint token 用共享 head 預測一個 latent 關節座標；每個關節有學出來的 twist 和 channel-mixing 矩陣，照 FK 的「右乘」結構把父 link 的特徵搬到子 link，加回 link token 後 LayerNorm；子 link 再更新驅動它的 joint token。
   - 作者在 supplementary 證明：用物理關節座標、物理 twist、identity channel mix、根部位姿當唯一非零初始特徵時，堆到樹的深度就能還原每個 link 的 FK（差一個二項式係數）。**在 policy 裡，只有樹的連接關係是固定的，twist 和 channel mix 都是 latent、學出來的**，所以不需要精確的機器人模型。
   - 週期性的 block 另外做 body self-attention（link token + global token）與 body-queried cross-attention。
4. **body-queried vision（§3.3）**：DINOv2 patch tokens 當 visual memory；每個關節用「自己的 joint token + 父 link 特徵」當 query，global token 給整體 query。query 依賴目前 action hypothesis，所以**去噪過程中，每個關節看的位置會跟著變**。多相機時，每個 view 的 patch 會標上「載著那支相機的 link」的特徵。
5. **body-aware action denoising（§3.4）**：最後的 schema 對每一維動作給一個條件；一個共享的 temporal decoder（FiLM 條件化的 Conv1D residual blocks）逐維預測雜訊。
6. **語言（§3.4）**：「when a language instruction is given」，用凍結的文字 encoder（例如 CLIP）在每個 block 後調變 joint 與 global token。語言是可選的條件，不是骨幹。
7. **推論（§3.5）**：快取和觀測有關的 visual K/V，每次去噪 pass 用 CUDA graph 重播；整個 chunk 執行完才看下一個觀測。16 步的 chunk 13.9 ms（RTX 6000 Ada）。Table 1 用 10 個 DDPM 步（訓練是 100 步）。

## 實驗與數字（作者自報，未經審查）

### 設定
- **SIMPLE**（模擬 Unitree G1）：9 個任務（抓取、雙手交接、移動抓取、全身搬運、推椅子、開門等），每個任務約 100 個示範；動作由 GR00T N1.6 附的 decoupled whole-body controller 執行。每任務 30 個固定 episode：L0 干擾物、L1 材質與光照、L2 物體與機器人位姿，各 10 個。
- **ManiSkill-HAB**（Fetch 移動機械手臂，底盤和軀幹是平移關節）：SetTable 的三個子任務（開冰箱、關冰箱、把物體放到**渲染在相機影像裡的目標標記**上）；輸入頭部與手部 RGB、關節狀態、**語言指令**；BSP、Rodrigues Network、DP 在約 25M 可訓參數下比較；3 個 seed，每 seed 1,008 個 episode。
- **真實 G1**：推推車並撿物、用腳踩開垃圾桶並丟進去；29 個身體關節 + 每手 7 DoF Dex3-1，共 43 個關節由 policy 下指令（經 HoloMotion v1.4 關節空間控制器）；頭戴 RealSense D435i；每任務 **15 個示範**、10 次試驗。

## 我對這篇的保留
1. **延遲比較的條件不對等**。BSP 的 13.9 ms 來自專門的 serving path（快取 visual K/V、CUDA graph）加 10 個 DDPM 步；DP 的 394 ms 很可能是 100 步、沒有同樣的工程最佳化。baseline 用什麼步數與實作，全文說在 supplementary（待查）。「快 10 倍」有多少來自架構、多少來自工程與步數，現在分不出來。比較公平的說法是：BSP 在**少步數下仍準**（第 5 步 < 2°），這才是架構帶來的。
2. **統計量很小**：SIMPLE 每任務每層級 10 個 episode、一個 seed；消融一個 seed；真實 G1 每任務 10 次。221 vs 220 是打平，不是贏。作者在 Limitations 承認 SIMPLE 沒有多 seed。ManiSkill-HAB 有 3 seed，是最可信的一組。
3. **和 foundation model 的比較是「單任務小模型 vs 微調後的大模型」**：BSP 每個任務從該任務示範訓練（作者寫「learns from the task's demonstrations alone」），Ψ₀ 有約 800 小時人類影片和 30 小時人形資料的預訓練。BSP 沒有多任務、沒有跨任務泛化的結果。
4. **去噪誤差是在訓練影格上量的**，只說明擬合速度，不說明泛化。
5. **依賴關節空間的動作語意**：作者在 Limitations 承認，換成 latent 空間指令的全身控制器（SONIC、BFM-Zero），body schema 效果變差（數字在 supplementary，待查）。
6. 它是 imitation learning，沒有世界模型、沒有 RL、沒有時序或週期結構。運動學樹處理的是**同一時刻的空間結構**，時間只在 temporal decoder 的 Conv1D 裡。

## 和我方向的關係

### 語言與任務指定
- SIMPLE 與真實 G1：作者沒有說有語言輸入，而且是**每個任務一個 policy**，所以任務靠「訓練資料就是那個任務」來指定（單任務 policy）。全文沒有明說 SIMPLE 上有無語言，嚴格說是待查 supplementary。
- ManiSkill-HAB：有語言指令（凍結 CLIP 調變 token），而且**放置任務的目標是畫在相機影像裡的標記**，等於視覺目標指定。
- 對 B 版：BSP 證明了「不需要語言骨幹也能在全身任務上追平 VLA」，但任務指定的問題它是用「單任務」繞開的，沒有解決。exemplar 指定任務仍是空位。主線 memo §8 的選項「單任務 policy」在這篇是實際被採用的做法，可以當 baseline 的形式。

### 對 Track B 關節角度先驗的啟示
- **「結構先驗取代規模」的引用**：35M 打平 2.63B（作者自報、未經審查），而且消融顯示拿掉 body schema 後，loco-manipulation 任務幾乎全失敗（LPBT 23 → 5、XMBP 28 → 0），雙手交接則差不多（24 → 19）。結構先驗的好處集中在**多部位必須協調**的任務。Track B 的論點（關節角度比外觀更適合描述動作）可以引用它當 policy 端的平行證據。
- **「DINOv2 的好處要靠 body schema 才釋放」**：沒有 body schema 時換 DINOv2 幾乎沒差（24 vs 20），有 schema 時 DINOv2 讓總分加倍（31 → 60/75）。對 Track B 的含義：關節結構和強視覺特徵是互補，不是取代。這支持 Track B 的 graceful degradation 設計：pose 可靠時用關節結構組織外觀特徵，而不是二選一。
- **每個部位讀自己的視覺證據**：這和 event memo 的「② 以關節為錨的局部 token」（借 EventPointMesh 的 Anchor Points，每個關節附近的 event 群組成一個 token）是同一個想法，只是 BSP 用 attention query 取代空間分組。BSP 的敏感度分析（手讀局部、底盤讀全景）給了一個可借用的驗證方式：在 event-ESC 或 Track B 上，檢查每個關節 token 是否只讀自己附近的區域。

### 對 P2（`z = [z_pose | z_res]`）的啟示
- **運動學樹 token + screw 傳遞，是 `z_pose` 的一個具體架構候選**。P2 目前只寫了「`z_pose` 回歸關節角度變化量」，沒有寫 `z_pose` 內部怎麼組織。BSP 的做法：每個關節一個 token、沿樹傳遞、twist 學出來，不需要精確的骨架模型。這正好適合 MediaPipe 骨架（拓撲已知，但沒有精確的關節軸和骨長）。
- **global token ↔ `z_res`**：BSP 用 global token 負責「不屬於任何關節的指令」（底盤速度），結構上就是 P2 的 `z_res`。差別是 BSP 的 off-tree 指令有明確語意（底盤速度），而 `z_res` 是「pose 描述不到的所有東西」，需要防止 `z_res` 把所有資訊吃掉（BAL 的 global/local 分解、[2611.18559-bal.md](2611.18559-bal.md)）。
- **Limitations 那一條對 P2 是重要證據**：控制器改用 latent 空間指令時，body schema 效果變差。也就是說，**結構先驗要有效，動作座標必須有運動學意義**。這支持 P2 把 `z_pose` 錨在關節角度變化量（有運動學意義），而不是讓 latent action 完全自由。反過來，這也提醒：`z_res` 的部分不會從 body schema 得到好處。數字待查 supplementary。
- **人的 pose 和機器人 proprioception 共用關節空間**：BSP 的 body schema 只依賴樹的拓撲，twist 是學的，所以同一套架構可以套在人的骨架樹和機器人的運動學樹上。但兩棵樹拓撲不同（MediaPipe 33 點 vs 手臂 6–7 DoF），共用的是「架構」，不是「token 對應」。要讓人的 pose 和機器人共用 latent，還需要一個樹之間的對應（例如人的肩–肘–腕對應手臂的前三個關節），這是 BSP 沒處理、P2 要處理的部分。作者把 cross-embodiment 列為未來工作。

### 能否搬到手臂
- 證據：Fetch（移動底盤 + 平移軀幹 + 手臂）上，matched size 下所有子任務、所有 seed 都贏 DP 和 Rodrigues（1.6–1.8 倍），這是最接近「手臂」的結果，而且有 3 seed。
- 但：BSP 的優勢在**多部位協調**的任務最大，單一手臂任務（例如 HAND 這類雙手交接，拿掉 schema 只從 24 掉到 19）優勢小。單手臂的週期性操作（擦拭、攪拌）是否也能受益，要看「同一條手臂上關節之間的協調」是否足夠讓結構先驗發揮。FK 外插實驗中，只有 revolute 關節的機器人上 Rodrigues 運算子反而較好（2–6 倍），一般手臂正是全 revolute，所以在純手臂上 screw 運算子的優勢不一定成立。

### 延遲／參數 vs Ψ₀、Diffusion Policy
- 作者自報：BSP 35M／13.9 ms；Ψ₀ 2.63B／148.2 ms；DP 84.3M／394.0 ms（模擬，RTX 6000 Ada）。真實 G1：BSP 17.4 ms、Ψ₀ 137 ms、DP 284 ms（RTX 5090）。
- 13.9 ms 一個 16 步 chunk，遠低於 30 Hz 的 33 ms，符合 B 版「即時、不靠大骨幹」的需求。但見保留 1：要拆開架構與工程的貢獻，才能引用成「結構先驗帶來低延遲」。可以安全引用的是「少步數下仍準」。

### 可以直接借用
- latent body schema 當 P2 `z_pose` 的架構候選；global token 當 `z_res` 的對應。
- 敏感度分析 + 遮蔽對照（遮最敏感的 10% vs 遮同量隨機 patch）：可以用在 Track B 或 event-ESC，檢查關節 token 是否真的讀自己的區域。和 LASR、swap probe 是同一類「條件變數有沒有用到它該用的內容」的對照。
- FK 外插實驗（訓練在關節範圍中間一半、測試全範圍）：可以搬到人體 pose，測 `z_pose` 在沒看過的動作幅度上是否還能正確組合。
- 「一個 encoder 單獨換掉沒差，加上結構才有差」的雙因子消融寫法（Table 4），可用來證明不可拆性（主線 memo §3「不可拆性檢查」）。

### 威脅或差異點
- 「以運動學樹或關節結構當 VA 介面」這個位置被它占了一部分（11-19 trends 已標記）。主力論文若在 policy 端用關節結構，必須引用並區分：BSP 是**同一時刻的空間結構**，用於 IL policy；我們是**跨時間的動作結構**（關節角度變化量的 latent action + 重複動作對應重複碼），用於世界模型與 latent action 預訓練。
- 它不用人體影片、不用 latent action、不做世界模型，所以不碰「從無標籤人體影片預訓練」那一段。
- 人形是我不做的平台；但 Fetch 的結果讓它不只是人形論文。

### 待驗證的想法（假說）
- **H1：把 MediaPipe 骨架樹當 body schema，學出的 latent twist 在週期動作上會呈現週期性。** 如果 joint token 預測的 latent 關節座標真的對應關節運動，週期動作中它應該和關節角度一樣有清楚的頻譜峰（可用 Track B Phase 0 的 peakiness 量）。這可以當 P2 `z_pose` 的「免監督也有運動學意義」測試。
- **H2：在純 revolute 的手臂上，screw 運算子相對一般 graph network 的優勢會縮小。** 依 FK 外插結果，全 revolute 機器人上 Rodrigues 運算子較好。若 B 版選手臂，要先用便宜的 FK 外插實驗確認該手臂上哪種運算子較好，再決定要不要用 screw。
- **H3：body-queried vision 在 pose 失效（遮擋、出框）時會退化得比 pooled 特徵更嚴重。** 因為每個關節的 query 依賴本體狀態，人體影片裡 pose 估計錯時，query 也跟著錯。機器人 proprioception 不會有這個問題，人的 pose 會。這是 P2 要加信心門控的直接理由，也是 BSP 沒測的情況。

## 後續要追的
- supplementary：baseline 的去噪步數與實作（決定延遲比較能否引用）、latent 空間控制器的數字、各任務分項、screw 閉式解、FK 等價證明。
